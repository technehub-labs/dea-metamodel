# CR-001 — Establish the Canonical DEA Metamodel

| Field | Value |
|---|---|
| Status | Implemented |
| Version | 0.6.0 |
| Depends on | — |
| Source | DEA Metamodel Remediation Programme, CR-1 (2026-08-16) |

## Objective

Establish a single authoritative source of truth for the DEA metamodel and eliminate
semantic/version divergence between the metamodel definition, entity schemas,
relationship schemas, SQLite schema, viewer graph, OpenDEAM root model, viewer
representations, and documentation.

**Principle:** There is one normative semantic model. Everything else is a
representation, projection, serialization, implementation, or visualization of it.

## Decisions (accepted 2026-08-16)

| # | Decision | Ruling |
|---|---|---|
| D1 | Authority model | dea-metamodel is the canonical *metamodel* authority; dea-architecture-framework remains the *enterprise-model* root upstream. One-way codified sync, documented in both repos. |
| D2 | Unified baseline version | **0.6.0** — all artifacts converge on it |
| D3 | Rollout shape | Phased additive — `metamodel/` tree lands alongside existing paths; legacy paths deprecated only after consumer migration |
| D4 | Generation scope | Validate-now, generate-where-generators-exist; full generator suite completes by CR-10 |
| D5 | Semantic ID scheme | `dea:Capability` (PascalCase entities, kebab-case relationships); legacy IDs kept as aliases |

## Implemented scope

- **CR-1.1** Normative source declared: `metamodel/dea-metamodel.yaml`; required rule
  stated in README, `docs/architecture.md`, and the normative file header.
- **CR-1.2** `metamodel/manifest.yaml` created (id, version 0.6.0, namespace,
  compatibility minimums, generated-artifact inventory).
- **CR-1.3** Component versions separated: metamodel / JSON Schema / SQLite projection /
  viewer — see `docs/versioning.md` and manifest `component_versions`.
- **CR-1.4** Semantic IDs assigned to all 54 entities and 17 relationships
  (`dea:BusinessCapability`, `dea:realizes`, …); legacy IDs preserved as aliases.
- **CR-1.5** Registries created: `metamodel/registry/entities.yaml`,
  `metamodel/registry/relationships.yaml`.
- **CR-1.6** Semantic expansion freeze declared (no new entity types until CR-003 closes).
- **CR-1.7** Versioning policy in `docs/versioning.md`, including the
  relationship-redefinition-is-semantic rule.
- **CR-1.8** This change-control mechanism (`change-requests/`).
- **CR-1.9** Conformance suite `tests/conformance/` (tests 001–006).
- **CR-1.10** Generation direction documented; existing generators wired to the
  normative source (Phase 3).
- **CR-1.11** CI enforcement: conformance suite + drift checks run on every PR.
- **CR-1.12** README restructured into Normative / Derived / Informative.
