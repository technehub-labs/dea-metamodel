# CR-002 — Establish the Authoritative Relationship Semantics

| Field | Value |
|---|---|
| Status | Implemented |
| Version | 0.7.0 |
| Depends on | CR-001 |
| Source | DEA Metamodel Remediation Programme, CR-2 (2026-08-16) |

## Objective

One authoritative, typed relationship ontology: every relationship has one semantic
meaning, defined direction, permitted source/target types, explicit cardinality,
metadata support, automated validation, and provenance — replacing the split
structural/instance vocabularies and undocumented viewer arrows.

## Implemented scope (sub-phases §23)

- **2A/2B** Inventory + classification: 70 edges / 59 labels extracted across all six
  representations; duplication audit of entity schemas and SQLite FK columns.
- **2C** `metamodel/migration/relationship-crosswalk.yaml`: all 59 viewer labels + all 10
  legacy instance-enum values explicitly dispositioned (accepted / review-required /
  split with alternatives). One label (`targets`) parked as NEEDS OWNER DECISION with
  alternatives listed.
- **2D** Canonical registry: 49 relationships (48 stored + 1 virtual inverse view) in the
  normative source with full §3 structure — category, direction, cardinality both ends,
  inverse, transitive/symmetric, temporal, provenance requirement, lifecycle.
- **2E** Schema implementation: `relationship-instance.json` v2 (metadata §6, agent
  provenance §22, lifecycle §20, mapping.kind §9); SQLite `relationships` table rebuilt
  from registry (48-type CHECK, metadata columns, deprecated columns retained for
  readability per 2G); TTL ObjectProperties regenerated (48).
- **2F** Entity cleanup: 35 duplicated relationship-state properties across 20 entity
  schemas marked `deprecated: true` with removal notice (CR-003).
- **2G** Migration: superseded types (`influenced-by`, `decomposes`) removed from the
  instance enum; crosswalk documents every conversion. Nothing silently reinterpreted.
- **2H** Validation: R001–R012 as conformance tests (37 tests total in suite), CI-gated.
- **2I** Viewer graph-side: every edge resolves to canonical `rel_ids` via the crosswalk
  (generator hard-fails on unknown labels — R012); graph embeds
  `relationship_definitions` for viewer definition display.

## Overloads resolved (§5, §17)

- `implements` was two rel_types at once → split: specification-satisfaction stays
  `implements`; `Guardrail→Control` became `operationalizes`; `Technology→AppComponent`
  became `supports`.
- `realizes` family disambiguated: realizes / implements / instantiates / represents /
  operationalizes are now distinct normative types.
- `governance` split into governs / mandates / controls / owns / responsible-for
  (+ accountable-for proposed).
- `maps-to` narrowed to crosswalk/classification/traceability with mandatory
  `mapping.kind`.
- `produces / consumes` and `publishes / subscribes` split into their component types.
- `funds` (appeared under two rel_types) unified to a single disposition (`supports`,
  review-required — funding semantics candidate for CR-8).
