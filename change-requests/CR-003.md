# CR-003 — Entity & Relationship Normalization

| Field | Value |
|---|---|
| Status | Implemented |
| Version | 0.8.0 |
| Depends on | CR-001, CR-002 |
| Source | DEA Metamodel Remediation Programme, CR-3 (2026-08-16) |

## Objective

Normalize the entity model so that entities represent things, relationships represent
semantic connections, attributes represent intrinsic properties, classifications
represent categorization, and instances represent concrete occurrences.

> Entity = what something is. Attribute = what it intrinsically has.
> Relationship = how it relates. Classification = how it is categorized.
> Instance = a concrete occurrence of a type.

## Implemented scope (phases §28)

- **Phase 1–2** Inventory + classification: 505 properties across 41 schemas classified
  into Identity (123) / Intrinsic (203) / Classification (55) / Relationship /
  Reference / Lifecycle / Derived — the classification rule of §30 is now mechanically
  answerable for every property.
- **Phase 3–4** Normalization + extraction: **70 relationship-state properties removed**
  from 25 entity schemas (37 CR-2F-deprecated + 32 ID-reference arrays + `maturity_level`).
  Every removal has a disposition in `metamodel/migration/entity-normalization.yaml`
  (58 property dispositions, target relationship or explicit re-assertion requirement).
- **CR-3B** `Capability.maturity_level` removed (SQLite projection too) — maturity moves
  to the Assessment model (CR-5).
- **CR-3O** all `owner` columns/properties removed — ownership via `dea:owns` /
  `dea:accountable-for` / `dea:responsible-for` relationships.
- **CR-3P** `external_references {system, identifier}` added to every entity schema;
  `stakeholder.external_identifiers` normalized into it; SQLite gains
  `entity_external_references` table. OpenDEA identity is independent of external systems.
- **CR-3R** centralized lifecycle vocabulary `metamodel/vocabularies/lifecycle.yaml`
  (proposed/planned/active/deprecated/retired); every entity schema carries
  `lifecycle_status` from it. `Technology.lifecycle_status` (approved/banned/…) renamed
  to `adoption_status` — adoption posture is a distinct classification.
- **E005** `metamodel/vocabularies/classifications.yaml` — 55 controlled classification
  vocabularies; schema enums must match exactly (CI-enforced).
- **CR-3M/E008** verified: layer membership is an attribute; no layer-based inheritance
  exists and the test now blocks it.
- **Phase 5–6** Type/instance + inheritance: schemas compose only against the abstract
  root (`entity.json`); circular inheritance impossible by construction (E006/E007).
- **Phase 8** Migration: `entity-normalization.yaml` carries source 0.7.0 → target 0.8.0,
  reversible: true, per-property transformation + rationale. Instance migration tooling
  is CR-10.
- **Phase 9** Validation: E001–E010 + lifecycle/maturity rules added; suite now 48 tests.
- **Phase 10** Viewer regeneration: graph regenerated from normalized model; edges still
  resolve to canonical rel_ids (CR-2); distinct visual semantics per category is
  dea-web-viewer follow-up work.

## Relationship endpoint extensions (normative, MINOR)

To receive migrated semantics: `supports.source += Actor`, `realizes.target +=
BusinessObject`, `represents.target += EcosystemActor`, `composes.target += Actor`,
`owns.target += BusinessProcess`, `informs.target += Entity` (semantic-dimension
wildcard). All endpoints remain within the 54 registered entities (CR-2 D3).
