# CR-004 — Establish the OpenDEA Core Ontology

| Field | Value |
|---|---|

## Objective

Define the small, stable, normative semantic core of OpenDEA — the concepts that answer
WHO / WHAT / WHY / HOW / WITH WHAT / FOR WHOM / UNDER WHAT CONSTRAINTS / WITH WHAT
INFORMATION / HOW IT CHANGES — separated from frameworks, viewpoints, classifications,
implementation concerns, and future extensions.

> OpenDEA Core defines stable semantic concepts; OpenDEA Profiles define specialized
> architectural viewpoints and frameworks.

## The Core (18 anchors)

**Existing anchors retained:** Entity, Actor, OrganizationalUnit, BusinessCapability,
Resource, FinancialResource, PhysicalResource, IntangibleResource.

**New abstract anchors:** ArchitectureElement (§5), Behavior (§9), Service (§10),
Information (§12), Organization (§7).

**New concrete anchors:** Decision (§13), Outcome (§14), Requirement (§15),
Constraint (§16), Change (§17) — each with JSON schema, SQLite table, pydantic model,
TTL class, lifecycle `proposed`.

## Profiles (10)

business · ecosystem · digital · data · technology · ai · governance · assessment ·
dmm (placeholder, CR-5) · ecf (classification viewpoint, CR-3S)

Every profile declares `depends_on` (all root at `dea:core`; no cycles — O004).
Profiles may extend/specialize; they must not redefine Core semantics (§29 — O002).

## Core relationship grammar (§19)

25-type subset of the canonical registry, incl. 5 new types added for the semantic
backbone (§20): `dea:makes`, `dea:results-in`, `dea:targets`, `dea:affects`,
`dea:contributes-to`. Backbone endpoints wired: Requirement/Constraint→constrains→
ArchitectureElement, Actor→performs→Behavior, Information→informs→Decision,
Decision→triggers→Behavior, Resource→enables→Capability, etc.
