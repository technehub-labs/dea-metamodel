CR-012 — Enterprise Intelligence & Advanced Agentic Runtime

Status: Proposed
Predecessors: CR-1 → CR-11 (all prior CRs in the canonical sequence)
Siblings: CR-013 (Digital Twin / Continuous Enterprise Model)
Primary objective: Make OpenDEA a continuously reasoning enterprise intelligence layer that combines semantic state, knowledge-graph reasoning, assessment maturity, federation, and governed agentic action — without absorbing external systems' semantics into the OpenDEA core (the same architectural principle as CR-11 §2).

⸻

1. Why CR-012 is the next logical phase

CR-9 gave OpenDEA an executable runtime (graph, reasoning, federation, agent governance).
CR-10 added scenario / impact / decision intelligence / agentic scenario proposals.
CR-11 added interoperability / federation / conformance — the ecosystem boundary.

What is still missing is the **production-grade composition layer** that ties these together:

- Continuous reasoning over the canonical semantic state (not just one-shot queries)
- Pattern detection across the live enterprise (recurring observation → interpretation → signal)
- Intelligent surfacing of maturity gaps, compliance drift, and risk to humans
- Governed agentic action: agents propose, never silently act
- The "intelligence loop" that the CR-10 §P conceptual stack describes (REPRESENT → UNDERSTAND → EVOLVE → GOVERN & ACT → CONTINUOUS ENTERPRISE)

CR-012 closes that loop.

The critical design principle is the same one CR-11 §2 stated:

    OpenDEA is the semantic contract; the intelligence layer absorbs complexity,
    never the core.

Therefore:

                         OPENDEA
                    Canonical Semantic
                         Contract
                            │
             ┌──────────────┼──────────────┐
             ↓              ↓              ↓
        Reasoning      Assessment      Federation
             ↓              ↓              ↓
       Intelligence   Maturity        Signals
       Patterns        Signals
             └──────────────┼──────────────┘
                            ↓
                  Governed Agentic Layer
                  (propose → approve → act)
                            ↓
                  Continuous Enterprise
                  Intelligence

The OpenDEA core stays stable; intelligence lives above it.

⸻

2. CR-012 architectural principle (binding)

Do not build this:

   Reasoning Engine absorbs OpenDEA semantics
   Assessment Engine absorbs OpenDEA semantics
   Agent Runtime absorbs OpenDEA semantics

Instead:

   Each engine consumes OpenDEA through its published runtime APIs
   (CR-9 §70, CR-9BX, CR-10 §N — "viewer/runtime/specification" layering)
   and emits governed signals back into the OpenDEA graph as
   Observations, Inferences, and Decisions — never by mutating the
   core semantic model.

This rule is already implicit in ADR-007 (Runtime/API separation) and ADR-008
(Inference ≠ authoritative knowledge). CR-012 makes it the **architectural
centrepiece** of the intelligence layer.

⸻

3. Scope of CR-012 (what it adds)

### 3.1 Continuous reasoning layer

- Recurring evaluation of reasoning rules against the live graph state
  (CR-9CP already requires reasoning to be request-scoped; CR-12 adds the
  **scheduled, observable** wrapper).
- Pattern library: declarative patterns that detect recurring situations
  (orphan capabilities, dormant integrations, maturity regression,
  authority misuse, mapping staleness).
- Observation stream: every reasoning cycle produces an *Observation*
  (not an *Inference* — see CR-9R/T) attached to the affected entity with
  provenance.

### 3.2 Signal taxonomy

A signal is an observation that has been promoted to **enterprise attention**.
CR-012 introduces a first-class `Signal` type:

    id
    observation_ref        (the Observation that produced it)
    classification         (maturity_gap | compliance_drift | risk |
                            capability_gap | federation_anomaly |
                            mapping_staleness | agent_anomaly)
    severity               (info | low | medium | high | critical)
    confidence             (exact | high | medium | low | uncertain)
    entities               (the affected canonical entities)
    rationale              (human-readable explanation)
    proposed_action        (optional — never auto-executed; CR-12 §3.4)
    owner
    status                 (open | acknowledged | in_review |
                            accepted | dismissed | resolved)
    raised_at
    acknowledged_at
    resolved_at

The classification is a vocabulary that *extends*, not redefines, CR-9's
provenance taxonomy. Signals are governed observations, not assertions.

### 3.3 Intelligence loop

The continuous enterprise intelligence loop:

    Live state → Reasoning cycle → Observations →
        Signal promotion (classification + severity + confidence)
            → Routing (owner / role / agent / scenario)
                → Governed action proposal (never silent)
                    → Audit
                        → Resolution → feedback into the graph

This loop is declarative (not a hard-coded process). Implementations can
short-circuit, replace components, or pause the loop. OpenDEA only governs
the *contract*: what enters, what exits, what is auditable.

### 3.4 Governed agentic action

Per CR-7 (decisions are first-class) and CR-9CR (agents are read-only by
default), every agent-initiated action must traverse the policy decision
point (CR-9AK ALLOW / DENY / ESCALATE) and be recorded as an audit entry.

CR-012 extends this with:

- **ActionProposal** — first-class artifact for agent-proposed mutations
  to the graph, scenarios, or integrations.
- **Approval workflow** — proposals carry status (`proposed | approved |
  rejected | executed | failed | withdrawn`), approver identity, timestamp,
  and rationale.
- **Execution boundary** — approved proposals are executed by the existing
  runtime APIs (CR-9AH), never by the agent directly.
- **Audit chain** — every proposal → approval → execution → outcome is a
  single traceable chain (CR-9AM extended with `proposalId`).

### 3.5 Intelligence governance

- Signals and proposals carry ownership, lifecycle, and policy references
  (CR-11AU vocabulary pattern applied to the intelligence layer).
- Owners must exist; dangling signals are an audit violation.
- The loop can be **paused**, **muted per classification**, or **escalated**
  per authority policy. A signal that no policy covers is rejected at the
  policy decision point, not silently dropped.

4. Explicit non-goals (binding)

- CR-012 is **not** an LLM orchestration framework. Agents that use LLMs
  consume the OpenDEA semantic context; OpenDEA does not host model
  inference (CR-9AD — OpenDEA governs *decision*, not *execution*).
- CR-012 is **not** an event stream processor. CR-11AF/AG already covers
  event interoperability; CR-012 consumes events as inputs to the
  reasoning cycle but does not redefine the event model.
- CR-012 is **not** a dashboard. Visualisation is the viewer's job
  (CR-9BX, ADR-007).
- CR-012 is **not** an assessment framework. CR-014 / CR-AM-02 own that
  scope; CR-012 surfaces assessment-derived signals but does not redefine
  maturity scoring.
- CR-012 is **not** the digital twin. CR-013 owns twin semantics. The
  intelligence loop runs *against* the live graph; the twin is a
  synchronised view (per CR-10 §28 CR-10AA boundary).

6. CR-012 design constraints

1. **Loop is declarative, not procedural.** The intelligence loop is
   describable in the metamodel (or a profile) — no hard-coded Python
   orchestration that consumers cannot override.
2. **Reasoning is bounded.** A reasoning cycle MUST declare its scope
   (entity types, relationship types, time window). Unbounded reasoning
   is rejected at registration (CR-9CP).
3. **Signals are first-class but governed.** A signal without owner /
   classification / confidence is a malformed observation.
4. **Proposals are reversible until executed.** Approval is a one-way
   gate. Pre-approval revisions are normal; post-execution reversal is
   a separate change scenario.
5. **The loop is auditable end-to-end.** Every signal, proposal,
   approval, and execution traces back to its observation and its
   reasoning cycle.
6. **Core is never extended.** The intelligence layer ships in its own
   `runtime/intelligence/` package with its own vocabulary file under
   `metamodel/profiles/intelligence/`. No addition to the 18 core anchors
   (CR-8 core-freeze, ADR-002).
7. **Backward compatible.** Existing CR-9 / CR-10 / CR-11 code paths
   continue to work unchanged. CR-012 is purely additive.

7. CR-012 proposed phases (for review)

CR-012 is large. Like CR-9 (10 sub-PRs), CR-10 (7 phases), and CR-11
(8 phases), it should ship in well-bounded phases. The proposed phase
breakdown is:

| Phase | Scope | Approx PR count |
|---|---|---|
| **1. Signal model** | `Signal` first-class type, classification/severity/confidence vocabularies, signal governance lifecycle | 1 PR |
| **2. Observation stream** | Reasoning cycle wrapper, observation emission from existing reasoning rules, observation-to-signal promotion | 1 PR |
| **3. Pattern library** | Declarative pattern definitions for the most common recurring situations (orphan capabilities, maturity regression, mapping staleness, federation anomalies, agent anomalies), each as a governed artifact | 1 PR |
| **4. Intelligence loop** | Declarative loop description, scheduler, observability, pause / mute / escalate controls | 1 PR |
| **5. Governed agentic action** | `ActionProposal` type, approval workflow, execution boundary via existing runtime APIs, audit chain extension | 1 PR |
| **6. Authority & routing** | Routing policies, owner / role / escalation resolution, mute / escalation policy registration | 1 PR |
| **7. Conformance** | New conformance class `Intelligence` (CR-12 conformance suite), fixtures, golden datasets | 1 PR |
| **8. Documentation** | `docs/intelligence/` set (overview, signal taxonomy, loop architecture, pattern catalogue, action proposals, governance, conformance, ADR-013 already shipped) + ADR-014 (intelligence-loop architecture) | 1 PR |

This is a proposal — phase boundaries may shift after review.
