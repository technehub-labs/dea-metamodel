## 1. Context

The OpenDEA Assessment Profile (`metamodel/profiles/assessment/profile.yaml`, `id: dea:assessment`, `version: 1.0.0`) is the vocabulary surface for assessment: it enumerates the `dea:Assessment*`, `dea:Maturity*`, `dea:Evidence*`, and `dea:Benchmark*` entities plus 13 relationships. Read alone, the profile gives no pointer to where the assessment sub-metamodel — the JSON Schemas, controlled vocabularies, maturity bands v2, governance policy, and CHANGELOG — actually lives.

That sub-metamodel now lives at `assessment-models/` in this same repo, since CR-014 landed it. CR-014 explicitly listed this cross-link as **out of scope** (CR-014 §3 Out of scope → "Future CRs may add forward-pointers from `metamodel/profiles/assessment/profile.yaml` to this sub-tree"). CR-015 is that pointer, scoped exactly: reciprocal, single repo, no schema or governance edits.

## 2. Why now

Closing the integration story:

1. A reader of the profile sees the vocabulary surface and would otherwise have to guess that the sub-tree exists.
2. A reader of `assessment-models/README.md` already sees the cross-reference table in §"Relationship to existing canonical content" (CR-014) but no reciprocal pointer at the profile layer.
3. CR-014 left this for a follow-on so it would not block that larger landing; closing it now completes the integration story before CR-MM-01 (Phase B maturity YAML with `legacy_name` aliases) lands underneath it.

## 3. Changes

### 3.1 `metamodel/profiles/assessment/profile.yaml`

A new top-level `cross_references:` block under the profile — alongside the existing `vocabulary_files:` block, since it has the same structural role (declares sibling artefacts this profile integrates with):

```yaml
cross_references:
- target: assessment-models/
  kind: internal-sub-tree
  relation: integrates_with
  doc_uri: relative  # file://relative within this repo
  canonical_url: https://github.com/technehub-labs/dea-metamodel/tree/main/assessment-models
  description: <see file>
  cross_ref_cr: CR-015
```

### 3.2 `assessment-models/README.md`

A new `### Upstream profile` subsection appended to `## Relationship to existing canonical content`, summarising: (a) the profile is the vocabulary contract; (b) the sub-tree is the schemas + conventions + governance + maturity bands; (c) future coupled additions should land in both places; (d) the split is a layering convention, not a multi-repo split.

## 4. Out of scope (re-stated)

- Profile content edits — none proposed. New `dea:` entities land in a separate CR.
- Sub-tree content edits — none. `CR-MM-01` (Phase B maturity YAML) is queued next and will reference CR-015 from its header.
- Any CI workflow changes — the existing canonical CI runs on push and on PR. This PR will trigger validate + typescript; the only thing the existing CI does with these files is documentation-read, which is unchanged.

## 5. Acceptance criteria

1. PR contains exactly two file changes: `metamodel/profiles/assessment/profile.yaml` (+`cross_references:` block) and `assessment-models/README.md` (+`### Upstream profile` subsection).
2. The two changes are reciprocal — both files reference each other by location.
3. Both files preserve existing content (no destructive edits).
4. Existing canonical CI passes (validate + typescript).
5. CHANGELOG `[Unreleased]` entry added documenting the reciprocal cross-link.
6. `change-requests/README.md` adds a row referencing CR-015 with status `Implemented` after merge.
